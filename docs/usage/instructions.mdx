---
title: "Custom Instructions"
description: "Guide Strix Web3 with custom audit instructions"
---

Use instructions to give context, deployment details, or focus areas for your audit.

## Inline Instructions

```bash
strix --target ./my-protocol --instruction "Focus on the oracle and share accounting"
```

## File-Based Instructions

For complex instructions, use a file:

```bash
strix --target ./my-protocol --instruction-file ./audit-instructions.md
```

## Common Use Cases

### Deployment Details

```bash
strix --target ./my-protocol \
  --instruction "The deployed proxy is at 0x1111... and the implementation at 0x2222... on Ethereum mainnet."
```

### Focused Scope

```bash
strix --target ./my-protocol \
  --instruction "Focus on rounding direction and share accounting in the vault, and on oracle staleness in the lending market."
```

### Exclusions

```bash
strix --target ./my-protocol \
  --instruction "The mocks/ directory and the vendored ./lib/are out of scope."
```

### Requiring a Proof

```bash
strix --target ./my-protocol \
  --instruction "Write a Foundry fork test against mainnet state for each High or Critical finding."
```

## Instruction File Example

```markdown instructions.md
# Audit Instructions

## Scope
- in-scope: src/vault/**, src/oracle/**
- out of scope: mocks/**, vendored ./lib/**

## Deployment
- Proxy: 0x1111111111111111111111111111111111111111 (mainnet)
- Implementation: 0x2222222222222222222222222222222222222222

## Focus Areas
1. ERC-4626 share inflation and donation attacks
2. Oracle read paths: spot vs TWAP, staleness, decimals
3. Access control on admin/config functions
4. Upgrade and initialization sequence

## Proof
- Fork tests against the pinned block in ETH_RPC_URL for every High/Critical finding.
```

<Tip>
Be specific. Good instructions help Strix prioritize the most valuable attack paths.
</Tip>

## Workspace files

Instructions become part of the prompt. To give Strix a file to work with, such
as a protocol specification, a prior audit report, or notes, use `--workspace-file`.
Strix places the file into the sandbox workspace before the audit starts.

```bash
strix --target ./my-protocol --workspace-file ./prior-audit.pdf
```

The file lands at `/workspace/<file name>`. To choose the destination, write
`PATH:DEST`. `DEST` is a path inside `/workspace`.

```bash
strix --target ./my-protocol \
  --workspace-file ./spec.pdf:docs/spec.pdf \
  --workspace-file ./notes.md
```

Repeat the option for every file you want to place. Strix lists the files in the
agent task, so the agent knows where to read them.

Rules that apply to every workspace file:

- Strix copies the file into the sandbox. The agent can edit the copy, but the
  file on your machine does not change.
- The destination must stay inside `/workspace`.
- The destination must not fall inside a target directory, because target files
  come from the target itself. Strix skips such a file and logs a warning.
- Two files cannot claim the same destination.

<Note>
A workspace file is data for the agent to use. It is not an audit target, and its
contents do not change the instructions.
</Note>

<Warning>
Do not place secrets in a workspace file. The sandbox runs untrusted target
code, so treat anything you place there as readable by the target.
</Warning>
