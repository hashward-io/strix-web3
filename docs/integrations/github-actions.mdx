---
title: "GitHub Actions"
description: "Run Strix Web3 contract audits on every pull request"
---

Integrate Strix Web3 into your GitHub workflow to catch contract vulnerabilities before they reach production.

## Basic Workflow

```yaml .github/workflows/audit.yml
name: Contract Audit

on:
  pull_request:

jobs:
  strix-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Strix (from source)
        run: |
          curl -LsSf https://astral.sh/uv/install.sh | sh
          git clone --depth 1 https://github.com/hashward-io/strix-web3 /tmp/strix-web3
          cd /tmp/strix-web3 && uv sync
          echo "/tmp/strix-web3/.venv/bin" >> "$GITHUB_PATH"

      - name: Build the sandbox image
        run: /tmp/strix-web3/scripts/docker.sh        # tags strix-sandbox:dev

      - name: Run Contract Audit
        env:
          STRIX_LLM: ${{ secrets.STRIX_LLM }}
          LLM_API_KEY: ${{ secrets.LLM_API_KEY }}
          ETH_RPC_URL: ${{ secrets.ETH_RPC_URL }}   # optional, for fork PoCs
        run: strix -n -t . --scope-mode diff --diff-base "origin/${{ github.base_ref }}" --max-budget 15
```

<Note>
  The job builds the sandbox image (`strix-sandbox:dev`) from
  `containers/Dockerfile` before the run. The full multi-chain image is large and
  slow to build on every PR — publish it to a registry once (or build it in a
  separate job) and set `STRIX_IMAGE` to the tag, or build only the EVM
  toolchains with `INSTALL_EXTRA_CHAINS=0 /tmp/strix-web3/scripts/docker.sh` for
  Solidity-only repositories.
</Note>

## Required Secrets

Add these secrets to your repository:

| Secret | Description |
|--------|-------------|
| `STRIX_LLM` | Model name (e.g., `openrouter/z-ai/glm-5.3`) |
| `LLM_API_KEY` | API key for your LLM provider |
| `ETH_RPC_URL` | Optional archive RPC endpoint, so fork proofs run against live state |

## Exit Codes

The workflow fails when findings are filed:

| Code | Result |
|------|--------|
| 0 | Pass — No findings (with `--fail-on`, none at or above the threshold) |
| 2 | Fail — Findings filed |
| 1 | Fatal error (setup, provider, or sandbox failure) |

Add `--fail-on high` (or `critical`, `medium`, `low`) to fail only on findings at or above that severity. Lower findings still appear in the report, so a passing run is not necessarily finding-free.

## Scan Modes for CI

| Mode | Duration | Use Case |
|------|----------|----------|
| `quick` | Minutes | Every PR (with `--scope-mode diff`) |
| `standard` | ~30 min | Nightly builds |
| `deep` | Hours | Release candidates, pre-deploy |

<Tip>
Use `quick` mode with `--scope-mode diff` for PRs to keep feedback fast. Schedule `deep` audits nightly or before a deploy.
</Tip>

<Note>
Strix Web3 audits the changed source files (in whatever ecosystem they belong to) in diff scope and uses the rest of the repository only as context. Fetch full history (`fetch-depth: 0`) or pass `--diff-base` explicitly so the merge base resolves.
</Note>
