---

Strix Web3 has access to a persistent bash terminal running inside the Docker sandbox. This gives the agent access to all [pre-installed audit tools](/tools/sandbox).

## Capabilities

| Feature           | Description                                                |
| ----------------- | ---------------------------------------------------------- |
| Persistent state  | Working directory and environment persist between commands |
| Multiple sessions | Run parallel terminals for concurrent operations           |
| Background jobs   | Start long-running processes without blocking              |
| Interactive       | Respond to prompts and control running processes           |

## Common Uses

### Building & Testing

```bash
# Build the project and run its existing tests
forge build
forge test -vvv

# Fuzz a target function
forge test --match-test testFuzz_Deposit -vvv

# Stateful invariant campaign
forge test --match-test invariant_ -vvv
```

### Static Analysis & Fuzzing

```bash
# Static analyzers seed leads, not verdicts
slither .
aderyn .

# Property-based and coverage-guided invariant fuzzing
echidna . --contract CryticTester
medusa fuzz

# Symbolic execution / bounded model checking
halmos
```

### Fork Proof-of-Concept

```bash
# Prove a bug against live mainnet state
forge test --match-test testExploit --fork-url "$ETH_RPC_URL" -vvvv

# Read or decode on-chain state directly
cast call 0xToken "balanceOf(address)(uint256)" 0xHolder --rpc-url "$ETH_RPC_URL"
cast 4byte-calldata 0xabcdef12
```

### Custom Scripts

```bash
# Run a Foundry script
forge script script/Exploit.s.sol --fork-url "$ETH_RPC_URL"

# Run a Python analysis / decoding script (web3, eth-abi)
python3 analyze.py
```

## Session Management

The agent can run multiple terminal sessions concurrently, for example:

- Main session for the build and test loop
- A secondary session for a long-running fuzzing campaign
- Background processes for an Anvil fork node or a watcher
